# Phase 0 — First do it

Ship the smallest Mu that is actually an agent.

## What landed

- Three packages: `mu.ai`, `mu.agent`, `mu.coding`
- Provider-neutral `Message` / `ToolCall` / `Event`
- `AgentLoop` parameterized over `Completer` and `ToolRunner`
- Four coding tools: `read`, `write`, `edit`, `bash`
- OpenAI-compatible `/chat/completions` via Python `urllib`
- `--fake` echo provider
- Print mode + REPL
- Append-only JSONL under `~/.mu/sessions/`
- `AGENTS.md` / `MU.md` folded into the system prompt
- Tests for text helpers, tools, the loop, and payload parsing

## Mapping to Pi / Tau

| Pi / Tau | Mu |
| --- | --- |
| `tau_ai` | `mu.ai` |
| `tau_agent` | `mu.agent` |
| `tau_coding` | `mu.coding` |
| `AgentHarness` | `AgentLoop` |
| `CodingSession` | CLI + `CodingRunner` + JSONL |
| Textual TUI | not yet; print + REPL only |
| streaming events | batched events after each turn |

## Deliberate shortcuts

- No async. Mojo 1.0 does not have it.
- No streaming. One HTTP request per model turn.
- JSON via CPython. Native parser comes later.
- `edit` does not restore original line endings or emit a unified diff.
- `bash` uses Python `subprocess` so timeout/capture work; Mojo `std.subprocess.run` only returns stdout.
- Sessions are append-only logs, not a resume/branch tree.

## How to try it

pixi run test
